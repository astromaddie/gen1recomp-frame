# Native Steam Frame kit tools

These tools build the ARM64 LÖVE 11.5 runtime and package only the native port
kit. The private game assembly is a separate player-local operation and is
never part of `package.py` output.

## Build runtime

The checked-in Dockerfile uses Ubuntu 22.04 and the input archives pinned by
`sources/SHA256SUMS`.

```sh
python3 tools/fetch-runtime-sources.py sources
docker buildx build --platform linux/arm64 -f tools/Dockerfile -t gen1recomp-frame-builder:latest .
tools/build-runtime.sh gen1recomp-frame-builder:latest /path/to/runtime-export
```

The export copies LÖVE and its non-platform transitive libraries, preserves
runtime notices, and rejects unresolved dependencies, non-AArch64 ELF files,
GL/driver libraries, glibc above 2.35, or GLIBCXX above 3.4.30. At launch,
SteamOS supplies its own loader, glibc, C++ runtime, graphics stack, and audio
system dependencies. The launcher puts the package libraries first in
`LD_LIBRARY_PATH`.

## Private local assembly

Fetch only the exact pinned engine and voxel source revisions into a fresh
external directory, then assemble into another fresh external directory:

```sh
python3 tools/fetch-private-sources.py /path/to/private-sources
python3 tools/assemble-local.py \
  --engine /path/to/private-sources/gen1recomp \
  --voxel /path/to/private-sources/DRAMALESS_SHAPE \
  --kit /path/to/gen1recomp-frame \
  --output /path/to/private-local-assembly
```

The assembly checks both revisions and clean checkouts, applies the native
`integration/main.lua.patch`, `integration/dramaless.patch`, plus `integration/src`, and writes a file hash
manifest. Keep it outside both this tools tree and the distributable package.
The game already supports player-provided ROM import through its file picker or
`POKEPORT_IMPORT_ROM=/absolute/path/to/legally-obtained-rom`; the variable is
consumed by the import path and does not copy the ROM into the kit. Never put
ROMs, extracted caches, or saves in package output or Git.

## Launch and package

The launcher defaults to required VR (`POKEPORT_VR_REQUIRED=1`). Use
`tools/LAUNCH-STEAM-FRAME.sh --flat` for a deliberate flat-mode run, or
`tools/LAUNCH-STEAM-FRAME.sh --probe` for the standalone runtime/bridge probe.
Startup output is recorded under `$XDG_DATA_HOME/logs/`; by default the
application-specific XDG directory is `~/.local/share/Gen1RecompFrame`. Set
`GEN1_FRAME_DATA_DIR` to choose it. The probe submits its labeled projection
when OpenXR reports `shouldRender`; `POKEPORT_XR_PROBE_DRY_RUN=1` explicitly
skips that submission. For one-shot source Canvas PNGs and copied swapchain
PPMs, set `POKEPORT_XR_PROBE_DUMP_DIR` to an absolute existing directory before
launching. The native side writes each eye at most once (8,388,608 pixels per
eye maximum), before releasing the OpenXR image. For a gameplay scene, set
`POKEPORT_XR_SWAPCHAIN_DUMP_AFTER_SUBMITS=60` to skip the launcher projection
and capture during the 60th successful projection submission; delays are capped
at 3,600 submissions. The normal game launcher does not enable diagnostics.

For an interactive startup failure, `POKEPORT_VR_STARTUP_TRACE=1` logs and
flushes load/Play/game-boot milestones and up to 180 once-per-second frame
samples. Each sampled frame records XR begin, update, draw and completion,
graphics availability, raw session/focus/render state, submitted-frame counts
and runtime errors. It does not bypass the launcher, inject input, force XR
rendering or change saved options. The VR launcher adapter stops forwarding
input immediately when Play or an editor callback replaces the launcher;
the new screen starts updating on the following frame. Callback failures
propagate to the normal error handler rather than being swallowed.

Build the bridge with the exact CMake inputs from the ARM64 builder image. The
script checks the produced ELF with `readelf`, then checks `ldd` with
`/usr/local` removed and the exported runtime libraries first in the search
path. Its build receipt binds the binary and dependency log to the builder image, Git head, and hashes of the CMake and C++ inputs.
Keep the build output outside the source tree:

```sh
tools/build-bridge.sh gen1recomp-frame-builder:latest \
  /path/to/gen1recomp-frame /path/to/runtime-export /path/to/bridge-output/xrbridge.so
```

Then package a fresh output directory outside the source tree:

```sh
python3 tools/package.py \
  --source /path/to/gen1recomp-frame \
  --runtime /path/to/runtime-export \
  --xrbridge /path/to/xrbridge.so \
  --output /path/to/native-kit-release
```

The packager requires the adjacent `xrbridge.build.json` and dependency-closure receipt generated by `build-bridge.sh`. It includes the native CMake/C++ sources and build helper, but downloaded runtime tarballs remain build inputs and only their checksum manifest ships. Packaging refuses dirty source by default. If the source is intentionally
uncommitted, pass `--allow-dirty`; the package metadata records the exact Git
status (including untracked files) and commit identity. The packager uses a
fixed path allowlist, requires the complete runtime license inventory, writes
`PACKAGE-METADATA.json` and a package-wide `SHA256SUMS`, and rejects user game
data. It does not copy `game/`, fetched voxel source, tests, build caches, or
arbitrary files from the source checkout.

## Presentation regressions

Use the pinned builder's LuaJIT and LÖVE. Pure production-camera tests also
read the pinned player-local voxel renderer; they do not alter it or need ROMs:

```sh
POKEPORT_XRBRIDGE=fake luajit integration/tests/presentation_test.lua \
  integration/src/vr /path/to/private-local-assembly/game/mods/DRAMALESS_SHAPE
POKEPORT_XRBRIDGE=fake luajit integration/tests/runtime_test.lua integration/src/vr/Runtime.lua
luajit integration/tests/runtime_loader_test.lua integration/src/vr/Runtime.lua
luajit integration/tests/telemetry_test.lua integration/src/vr/Telemetry.lua
luajit integration/tests/runtime_telemetry_test.lua integration/src/vr/Runtime.lua
luajit integration/tests/vr_telemetry_driver_test.lua integration/tests/vr_telemetry_driver.lua
POKEPORT_VR_REQUIRED=1 luajit integration/tests/main_overlay_test.lua /path/to/private-local-assembly/game/main.lua
POKEPORT_VR_REQUIRED=1 luajit integration/tests/launcher_transition_test.lua /path/to/private-local-assembly/game/main.lua /path/to/private-local-assembly/game/src/import/RomImporter.lua
luajit integration/tests/startup_trace_test.lua integration/src/vr/StartupTrace.lua
luajit integration/tests/probe_policy_test.lua integration/probe/main.lua
```

Build a separate bridge with `-DXRBRIDGE_TESTING=ON` using the same CMake
inputs as `build-bridge-in-container.sh`; never package that test binary.
With `POKEPORT_XRBRIDGE` pointing to it, run `love integration/tests/canvas_copy`
under Xvfb both without diagnostics (MSAA, unreadable and scaled copies) and
with `POKEPORT_XR_PROBE_DUMP_DIR` set to a fresh directory (one-shot PPM
orientation/readback-state checks). The original native copy fails the
OpenXR-origin expectation. Set `POKEPORT_VR_TELEMETRY=1` for an additional
asynchronous timestamp-query test that brackets 64 real LÖVE-batched draws.
The normal ARM64 bridge build also runs an Xvfb `package.loadlib` factory smoke
against the exported runtime without creating an OpenXR instance, and rejects
unresolved dynamic symbols with `ldd -r`.

For the rendered mono regression, set `POKEPORT_TEST_KIT` to this checkout,
`POKEPORT_TEST_OUTPUT` to a fresh evidence directory, and
`POKEPORT_XR_PROBE_DUMP_DIR` to that same directory, then run
`love integration/tests/mono_panel`. Inspect `panel-left.png`,
`panel-right.png` and the normalized `xr-left.ppm`/`xr-right.ppm`. Different
pixel offsets and scale in asymmetric eye images are expected: the test
checks that both projections reconstruct the same upright physical plane.
These host checks do not substitute for corrected Frame/wearer acceptance.

Run `love integration/tests/hud_projection` under the same LÖVE/Xvfb runtime
with `POKEPORT_TEST_KIT`, `POKEPORT_TEST_ENGINE`, `POKEPORT_TEST_VOXEL`,
`POKEPORT_TEST_OUTPUT` and `POKEPORT_XRBRIDGE=fake`. It executes the pinned
Minimap, Renderer, Player pose and finishStereo source, records the original
texture-space placement mismatch, and checks physical HUD/dialogue correspondence
at several rolls plus the staged battle dispatch and scoped method restoration.
The map/dialogue colors are analytic fixtures; game artwork is not included.

The host foveation protocol test compiles the actual bridge translation unit and
uses strict XR callbacks to validate profile chains, unchanged 1728² targets,
eye/fixed/off/unsupported cases, second-eye failures, symmetric full-rate recovery,
and handle cleanup. This is protocol proof, not a GPU performance measurement:

```sh
docker run --rm --platform linux/arm64 -v "$PWD:/kit:ro" \
  gen1recomp-frame-builder:latest bash -c '
  set -e
  g++ -std=c++17 -O1 -DXRBRIDGE_LOVE_ABI_11_5=1 \
    -I/opt/openxr/include -I/usr/include/luajit-2.1 \
    -I/opt/love-11.5/src -I/opt/love-11.5/src/modules \
    /kit/integration/tests/native_foveation.cpp /kit/vrbridge/VisibilitySelection.cpp -ffp-contract=off -L/opt/love/lib \
    -llove-11.5 -lluajit-5.1 /opt/openxr/lib/libopenxr_loader.a \
    -lGL -lX11 -ldl -pthread -o /tmp/foveation-test
  LD_LIBRARY_PATH=/opt/love/lib /tmp/foveation-test'
```

For Frame comparison, preserve native eye dimensions and scene, use
`POKEPORT_XR_FOVEATION=eye` versus `off`, and collect `FDM_DEBUG` output from the
Valve injection layer. Verify source eye render-pass attachment before attributing
any timing difference to foveated rendering. Runtime API acceptance alone is not
sufficient. `fixed` is a diagnostic fallback, not an eye-tracking claim.

For conservative frustum selection, run `love integration/tests/draw_distance`
with `POKEPORT_TEST_KIT` and `POKEPORT_TEST_VOXEL` under the pinned LÖVE/Xvfb
runtime. Its real indexed mesh tests cover ordered vertex selection, whole
visible boundary geometry, original shadow mesh preservation, stereo readiness,
neighbor translation, and cache invalidation.

`integration/tests/draw_distance/scene_driver.lua` runs inside a private assembled
game with the copied Yellow slot1 and player-owned import cache. Set
`GEN1_FRAME_DRIVER_UTIL` to `integration/tests/driver_util.lua`, `SHOT_DIR` to a
fresh output directory, and start with `POKEPORT_VR=0`, `POKEPORT_XRBRIDGE=fake`.
The driver switches to a fake native frame boundary with real 1728² eye Canvases,
then compares the actual pinned VoxelScene/ChunkMesher/render passes with culling
off/on in the same game update with rendering time, delta and the DayNight SYNC
clock frozen. Optional `QA_MAP`, `QA_X`, `QA_Y`, `QA_YAW`, `QA_PITCH`, `QA_ROLL`,
`QA_SHIFT` and `QA_CURVE` vary the scene and tracked pose. Counts are per complete stereo pair, with main and shadow draws
reported separately, with exactly two successful stereo scenes per capture.
Full eye images must agree within 0.02 aggregate RGB; max/mean channel errors
and nonzero pixel counts are also reported. `QA_CONTROL=1` compares off/off
to isolate draw-time animation or state changes.
Private art and screenshots never belong in the distributable kit.

## DRAMALESS replacement checks

Use `integration/tests/dramaless_scene_driver.lua` with the private new assembly
and an isolated copy of player data. It captures one culled stereo pair (no
whole-map comparison run), asserts two actual VoxelScene passes and matching
source GPU telemetry scopes, checks once-per-frame glint/player animation,
and steps R.DIST through the existing Options row. `QA_MAP`, `QA_X`, `QA_Y`,
`QA_YAW`, `QA_PITCH`, and `QA_ROLL` select the host scene/pose. Captures use
1728-square eyes. Keep these screenshots and player data outside the kit.

The continuous device driver `vr_telemetry_driver.lua` calls the updated
DRAMALESS `saved_scene.lua`, prints its initial measurement marker, and yields
forever afterward while CPU/GPU collection continues. Only the user ends the
settings-tuning session; do not add a diagnostic auto-quit.

## Shadow and frame-order regressions

Run `love integration/tests/shadow_cache` under the same LÖVE/Xvfb environment
with `POKEPORT_TEST_VOXEL` pointing to the newly assembled DRAMALESS directory.
It runs the actual shadow shader, fitter and canvas lifecycle. The original
unpatched source must fail the retained-target assertion at a larger size rung.
`main_overlay_test.lua` also exercises the actual `love.run` order: current XR
time/focus, inactive graphics, update/draw errors, skipped/direct draws and flat
wall-clock fallback. `native_foveation.cpp` includes the bounded CPU-stage clock
collection/transfer/reset check against the actual bridge translation unit.

`integration/tests/performance_scene_driver.lua` uses the same private copied-save
host setup and pose environment as `dramaless_scene_driver.lua` (`QA_LEVEL` also
selects a camera rung). It compares unguarded water and the old compulsory shadow
redraw behavior against the corrected path, within one update with clocks frozen.
The baseline forces shadow invalidation only when the fitted target is above
1024; the original target-allocation bug is tested independently. Both captures
retain existing terrain frustum selection. It reports full-image error, actual
shadow/reflection pass counts and source triangle counts, then verifies actor
movement/restoration and outdoor lighting invalidate the real scene cache.
Do not interpret software-GL host timings as Steam Frame performance.


For the terrain/dynamic shadow split, run `love integration/tests/shadow_optimization`
with `POKEPORT_TEST_KIT`, `POKEPORT_TEST_VOXEL` and `POKEPORT_TEST_BRIDGE` pointing to
this kit, its private assembled DRAMALESS directory, and the newly compiled native
bridge. It executes the actual shader and exact GPU depth-copy helper; checks
coplanar ties, alpha/sprite classification, actor movement, fit/resolution changes,
copy state preservation and type/target/format/alias/failure fallback. The existing
`draw_distance` test also covers light-volume selection and off-eye casters.

`integration/tests/shadow_scene_driver.lua` uses the private scene workflow above,
with `POKEPORT_TEST_BRIDGE` for the actual color/depth copy and a fake OpenXR pose
boundary. Both sides retain the bf5 terrain-view and reflection selection. It
compares the unchanged combined sun pass against cold and warm split caches at
1728² per eye, then moving player/NPCs, actual atlas animation and outdoor light/
camera changes. Use city, Route21 visible water, a rolled Mart interior and POV.
Every comparison freezes update/time and reports full-image exact differences,
shadow rebuild/cache/triangle counts and reflection passes. A static interior
without an animated atlas is reported explicitly, not counted as animation proof.

The native factory regression now checks retained eye-profile lifetime, production
`beginFrame` wait/begin/locate/update-both/query ordering, repeated frames, failed
second-eye refresh/query, invalid gaze, raw focus/render gates and authorized
unattended refresh. It also verifies fixed/off/missing-optional-API fallback. Run
`vrbridge/tests/telemetry_test.cpp` for bounded nested source/shadow GPU timestamps.
The opt-in source-eye dimensions and AA attribution cannot prove Valve FDM attachment;
that requires the booked Frame capture/diagnostics and worn validation separately.

Renderer CPU diagnosis: run `luajit integration/tests/renderer_motion_driver_test.lua
integration/tests/renderer_motion_driver.lua` and the existing telemetry/runtime
regressions before packaging. The bounded device driver is
`integration/tests/renderer_motion_driver.lua`, with `POKEPORT_SAVED_SCENE_DRIVER`
and `GEN1_FRAME_DRIVER_UTIL` set to the private saved-scene loader and public
helper, and `POKEPORT_VR_TELEMETRY=1`. Allow saved-scene startup plus eight seconds
warmup and 32 seconds measurement. Read actual movement/scene/settings/eye-size
records before comparing standing and walking. It keeps yielding after completion
for evidence collection; the operational owner terminates its owned process.

Native visibility checks: compile `vrbridge/tests/visibility_test.cpp` with
`vrbridge/VisibilitySelection.cpp`, C++17 and `-ffp-contract=off`. Run the existing
LOVE `draw_distance` regression with `POKEPORT_TEST_BRIDGE` set to the candidate
module and `POKEPORT_TEST_CULL_BASELINE` to the frozen previous selector. It checks
real ByteData rejection/lifetime, 80 moving stereo/light ordered-index cases,
curved terrain, separate GPU buffers, reusable allocation and native rejection
fallback. `stereo_lifecycle_test.lua` exercises production stereo success, error
and nonrenderable cleanup with a controlled graphics boundary.

For complete same-update renderer comparisons, the private `shadow_scene_driver`
also accepts `POKEPORT_TEST_STEREO_BASELINE` and `POKEPORT_TEST_SCENE_BASELINE`,
pointing to the prior adapter and already patched private VoxelScene. This mode
uses MEDIUM32/FULL/AAoff, compares moving tracked poses and game camera/player,
NPC/atlas animation and lighting, and records actual preparation counts and native
use. It does not hot-edit selector closure upvalues for timing: that QA profiler
can fault ARM64 LuaJIT when combined with scene-module swapping. Use the production
exclusive stages for selector timing and keep host software-GL cost separate from
Frame measurements. Source/header kernel hashes are included in native build and
package receipts.


## Launcher pointer and battle stereo regressions

`launcher_pointer_test.lua integration/src/vr` exercises physical ray geometry
and click latching. `launcher_transition_test.lua` requires a fresh assembly:
it now runs the original trigger-to-Play callback, original importer cursor/scroll
update, and original gameplay input isolation in addition to A/pad/mouse paths.
Run `battle_stereo_test.lua integration/src/vr <assembled-mod>` for the actual
standalone host's two-eye-only dispatch, once-only UI/update/capture, error cleanup
and session reset. Build `native_pointer.cpp` with the same translation-unit
command as `native_foveation.cpp` above to test native bindings/pose lifecycle.

Run `love integration/tests/launcher_pointer` under Xvfb with POKEPORT_TEST_KIT
and POKEPORT_TEST_OUTPUT. For the actual importer render, copy that test's main.lua
and conf.lua into a disposable private assembled game, set POKEPORT_TEST_ENGINE=1,
and run that copy: it needs the original source/assets at the LÖVE source root.
No player cache or ROM is required for the importer image.

`battle_scene_driver.lua` uses the established isolated copied-Yellow-save host
workflow. Set POKEPORT_TEST_BRIDGE to a native module for the existing visibility
kernel, POKEPORT_DRIVER to this driver, GEN1_FRAME_DRIVER_UTIL to driver_util.lua,
and SHOT_DIR to a private evidence directory. It renders at 1728², compares full
images under equal poses with visibility selection off/on, records actual card
bounds/IPD/pass counts, exercises original Fight/B actions and battle exit/re-entry.
The synthetic pose changes before the following XR frame is prepared; do not
compare two draws across a pose change inside one update.

For the battle comfort repair, run `battle_presentation_test.lua
integration/src/vr` and `battle_scale_test.lua integration/src/vr` with LuaJIT
and `POKEPORT_XRBRIDGE=fake`. The battle scene driver additionally loads
`battle_depth_probe.lua` beside `driver_util.lua`; this QA-only helper checks the
actual scene-depth/HUD ordering, including downward pitch. Set `POKEPORT_QA_MAP`
to `PEWTER_GYM` for the interior fixture. To test existing player settings, copy
them to the isolated test data directory's `options.lua` **before launching**
LÖVE; late `Game:applyOptions` does not invalidate the mod's cached settings.
Set `POKEPORT_QA_EXPECT_RES=4` for a copied RES4 configuration, or `1` for the
source default FULL configuration. The driver asserts the live value.
The source-only package allowlist already carries every overlay module; no
new runtime dependency, native ABI, asset or package rule is required.
The host driver drains the original incremental terrain pump during fixture
setup, before starting the authoritative transition; it asserts an empty mesh
queue and ready terrain. Every transition and battle logic tick follows the
original update path. The QA driver draws asserted transition stages, the first
battle presentation, required stereo comparisons and return effects; it omits
redundant intro raster work between captures. Eye size and scene geometry remain
unchanged. These are host test shortcuts, not production performance changes.

For the camera setback check, run `POKEPORT_XRBRIDGE=fake luajit
integration/tests/camera_setback_test.lua integration/src/vr <assembled-mod>`.
It uses the current pinned FirstPerson camera and the Frame stereo adapter,
checks all three camera modes, and preserves physical IPD and world scale.
