# Native Steam Frame kit tools

These tools build the ARM64 LÖVE 11.5 runtime and package only the native port
kit. The private game assembly is a separate player-local operation and is
never part of `package.py` output.

## Build runtime

The checked-in Dockerfile uses Ubuntu 22.04 and the input archives pinned by
`sources/SHA256SUMS`.

```sh
python3 tools/fetch-runtime-sources.py sources
docker buildx build --platform linux/arm64 -f tools/Dockerfile -t gen1recomp-frame-builder:latest .
tools/build-runtime.sh gen1recomp-frame-builder:latest /path/to/runtime-export
```

The export copies LÖVE and its non-platform transitive libraries, preserves
runtime notices, and rejects unresolved dependencies, non-AArch64 ELF files,
GL/driver libraries, glibc above 2.35, or GLIBCXX above 3.4.30. At launch,
SteamOS supplies its own loader, glibc, C++ runtime, graphics stack, and audio
system dependencies. The launcher puts the package libraries first in
`LD_LIBRARY_PATH`.

## Private local assembly

Fetch only the exact pinned engine and voxel source revisions into a fresh
external directory, then assemble into another fresh external directory:

```sh
python3 tools/fetch-private-sources.py /path/to/private-sources
python3 tools/assemble-local.py \
  --engine /path/to/private-sources/gen1recomp \
  --voxel /path/to/private-sources/DramaticShapeVoxelMod \
  --kit /path/to/gen1recomp-frame \
  --output /path/to/private-local-assembly
```

The assembly checks both revisions and clean checkouts, applies the native
`integration/main.lua.patch` plus `integration/src`, and writes a file hash
manifest. Keep it outside both this tools tree and the distributable package.
The game already supports player-provided ROM import through its file picker or
`POKEPORT_IMPORT_ROM=/absolute/path/to/legally-obtained-rom`; the variable is
consumed by the import path and does not copy the ROM into the kit. Never put
ROMs, extracted caches, or saves in package output or Git.

## Launch and package

The launcher defaults to required VR (`POKEPORT_VR_REQUIRED=1`). Use
`tools/LAUNCH-STEAM-FRAME.sh --flat` for a deliberate flat-mode run, or
`tools/LAUNCH-STEAM-FRAME.sh --probe` for the standalone runtime/bridge probe.
Startup output is recorded under `$XDG_DATA_HOME/logs/`; by default the
application-specific XDG directory is `~/.local/share/Gen1RecompFrame`. Set
`GEN1_FRAME_DATA_DIR` to choose it. The probe submits its labeled projection
when OpenXR reports `shouldRender`; `POKEPORT_XR_PROBE_DRY_RUN=1` explicitly
skips that submission. For one-shot source Canvas PNGs and copied swapchain
PPMs, set `POKEPORT_XR_PROBE_DUMP_DIR` to an absolute existing directory before
launching. The native side writes each eye at most once (8,388,608 pixels per
eye maximum), before releasing the OpenXR image. For a gameplay scene, set
`POKEPORT_XR_SWAPCHAIN_DUMP_AFTER_SUBMITS=60` to skip the launcher projection
and capture during the 60th successful projection submission; delays are capped
at 3,600 submissions. The normal game launcher does not enable diagnostics.

Build the bridge with the exact CMake inputs from the ARM64 builder image. The
script checks the produced ELF with `readelf`, then checks `ldd` with
`/usr/local` removed and the exported runtime libraries first in the search
path. Its build receipt binds the binary and dependency log to the builder image, Git head, and hashes of the CMake and C++ inputs.
Keep the build output outside the source tree:

```sh
tools/build-bridge.sh gen1recomp-frame-builder:latest \
  /path/to/gen1recomp-frame /path/to/runtime-export /path/to/bridge-output/xrbridge.so
```

Then package a fresh output directory outside the source tree:

```sh
python3 tools/package.py \
  --source /path/to/gen1recomp-frame \
  --runtime /path/to/runtime-export \
  --xrbridge /path/to/xrbridge.so \
  --output /path/to/native-kit-release
```

The packager requires the adjacent `xrbridge.build.json` and dependency-closure receipt generated by `build-bridge.sh`. It includes the native CMake/C++ sources and build helper, but downloaded runtime tarballs remain build inputs and only their checksum manifest ships. Packaging refuses dirty source by default. If the source is intentionally
uncommitted, pass `--allow-dirty`; the package metadata records the exact Git
status (including untracked files) and commit identity. The packager uses a
fixed path allowlist, requires the complete runtime license inventory, writes
`PACKAGE-METADATA.json` and a package-wide `SHA256SUMS`, and rejects user game
data. It does not copy `game/`, fetched voxel source, tests, build caches, or
arbitrary files from the source checkout.

## Presentation regressions

Use the pinned builder's LuaJIT and LÖVE. Pure production-camera tests also
read the pinned player-local voxel renderer; they do not alter it or need ROMs:

```sh
POKEPORT_XRBRIDGE=fake luajit integration/tests/presentation_test.lua \
  integration/src/vr /path/to/DramaticShapeVoxelMod
POKEPORT_XRBRIDGE=fake luajit integration/tests/runtime_test.lua integration/src/vr/Runtime.lua
POKEPORT_VR_REQUIRED=1 luajit integration/tests/main_overlay_test.lua /path/to/private-local-assembly/game/main.lua
luajit integration/tests/probe_policy_test.lua integration/probe/main.lua
```

Build a separate bridge with `-DXRBRIDGE_TESTING=ON` using the same CMake
inputs as `build-bridge-in-container.sh`; never package that test binary.
With `POKEPORT_XRBRIDGE` pointing to it, run `love integration/tests/canvas_copy`
under Xvfb both without diagnostics (MSAA, unreadable and scaled copies) and
with `POKEPORT_XR_PROBE_DUMP_DIR` set to a fresh directory (one-shot PPM
orientation/readback-state checks). The original native copy fails the
OpenXR-origin expectation.

For the rendered mono regression, set `POKEPORT_TEST_KIT` to this checkout,
`POKEPORT_TEST_OUTPUT` to a fresh evidence directory, and
`POKEPORT_XR_PROBE_DUMP_DIR` to that same directory, then run
`love integration/tests/mono_panel`. Inspect `panel-left.png`,
`panel-right.png` and the normalized `xr-left.ppm`/`xr-right.ppm`. Different
pixel offsets and scale in asymmetric eye images are expected: the test
checks that both projections reconstruct the same upright physical plane.
These host checks do not substitute for corrected Frame/wearer acceptance.
